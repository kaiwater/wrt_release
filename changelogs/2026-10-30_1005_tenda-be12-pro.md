## 为什么要 BASE_CONFIG

Sun-flower1/immortalwrt-tenda-be12-pro 本身不是完整 OpenWrt 源码树，而是一个 builder：

- 上游 defconfig：`defconfig/low-mem-512m/mt7987-mt7992-be7200.config`
- 再叠加自己的 `.config` 增量
- `diy.sh post` 负责合并，并剔除 Routerich 设备

本仓库新增了通用的 `BASE_CONFIG` / `BASE_CONFIG_FILTER` 机制：

```ini
BASE_CONFIG=defconfig/low-mem-512m/mt7987-mt7992-be7200.config
BASE_CONFIG_FILTER=routerich_be7200,luci-app-eqos-mtk
```

构建顺序变为：

```text
上游 BASE_CONFIG
  → 按 BASE_CONFIG_FILTER 剔除不需要的机型/包
  → 设备 delta (.config)
  → compile_base.config
  → fragments
```

这样 BE12 Pro 可以复用上游完整的 Wi-Fi 7 Kconfig（否则 hostapd 的 MLO/802.11be 补丁无法编译），同时继续使用本项目的 app 软件包规划。

## App 规划

BE12 Pro 使用：

- `compile_base.config`
- `proxy.config`
- 公共 LuCI / 工具 / 插件
- 上游 base 提供的：
  - `luci-app-mtwifi-cfg`
  - `luci-app-turboacc-mtk`
  - `kmod-mt_wifi7`
  - `kmod-mt7992`
  - `wifi-profile` / `l1profile`
  - `warp` / `hwifi`

没有加入 `usb_storage`，因为 BE12 Pro DTS 没有 USB host 节点。

## 默认 WiFi

上游 `mtwifi.uc` 首次启动默认创建开放 AP。新增 `fix_mtwifi_security_defaults()`：

- 检测 `package/mtk/applications/mtwifi-cfg-ucode/files/lib/wifi/mtwifi.uc`
- 把：

```ucode
"encryption": "none"
```

改为：

```ucode
"encryption": "psk2", "key": "kaiwater/wrt_release"
```

只在 mtwifi 源码存在时生效；其他平台不受影响。

## 风险

- 上游 `25.12-dev-wifi7` 是快速变化的 Wi-Fi 7 分支，base defconfig 可能随上游变化；使用 `BASE_CONFIG` 可以避免把整份上游配置写死，但首次构建仍需验证。
- BE12 Pro 首次构建没有缓存，耗时会较长。
- `mtwifi.uc` 的默认开放 AP 被改为 `psk2`，如果上游接口字段变化，脚本会打印警告并保留上游默认，不会阻塞编译。
- BE12 Pro 的 `sysupgrade.bin` 依赖上游 `tenda-mkdualimageheader`；本仓库不额外生成 factory 镜像。
