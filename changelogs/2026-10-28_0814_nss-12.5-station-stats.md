# 2026-10-28 08:14 — 修复 NSS 12.5 下 station dump 速率/信号丢失

## 现象

ipq60xx（jdcloud）和 ipq807x（AP8220 / AX3600）共用 NSS 12.5 构建，运行几个小时后：

```sh
iw dev phy0-ap0 station dump
```

输出中缺少：

- `rx bitrate`
- `tx bitrate`
- `expected throughput`

同时 `tx duration: 0 us`、`rx duration: 0 us`，`signal avg` 也可能异常（例如 `signal -39 dBm`、`signal avg -95 dBm`）。`rx bytes` / `tx bytes` 长时间几乎不增长。

## 根因一：ath11k 没有使用 NSS 12.5 的 peer stats 结构体

LibWrt 的 `package/kernel/mac80211/Makefile` 只处理了 11.4：

```make
ifeq ($(CONFIG_NSS_FIRMWARE_VERSION_11_4),y)
    C_DEFINES+=-DCONFIG_NSS_FIRMWARE_VERSION_11_4
endif
```

但没有给 12.5 加定义。而 qca-nss-drv 和 ECM 的 Makefile 都会加：

```make
ifdef CONFIG_NSS_FIRMWARE_VERSION_12_5
    EXTRA_CFLAGS += -DNSS_FIRMWARE_VERSION_12_5
endif
```

`nss-packages` 的 `exports/nss_wifili_if.h` 在 `NSS_FIRMWARE_VERSION_12_5` 下会多出：

```c
/* nss_wifili_rx_ctrl_stats */
uint32_t ucast_rcv_cnt;
uint32_t ucast_rcv_bytes;

/* nss_wifili_retry_ctrl_stats */
uint32_t tx_mpdu_retry_count;
uint32_t tx_mpdu_total_retry_count;
```

每个 peer 的统计结构因此多 16 字节。ath11k 没有同样的宏，仍按旧结构体解析 firmware 发来的 peer stats：

- 第一个 peer 之后的数据整体错位
- peer_id 对不上，统计被丢弃或归到错误 peer
- RX 速率、RX/TX 计数、last_rx、inactive time 等逐渐失效
- `iw station dump` 最终没有速率和有效信号

这解释了为什么问题在 ipq60xx 和 ipq807x 上共享，并且运行一段时间、客户端数量变化后才明显。

## 根因二：qca-nss-pbuf 默认关闭 ath11k 统计

`qca-nss-pbuf` 默认：

```sh
config_get stats_disable opt stats_disable 1
```

启动或重启时会把 `stats_disable=1` 写入 ath11k debugfs，关闭数据包统计以换取吞吐。这会进一步导致 station dump 的速率、信号变为 0 或消失。

## 修复

### 1. 给 ath11k 补上 NSS 12.5 定义

`wrt_core/modules/target_fixes.sh` 新增 `fix_ath11k_nss_stats_layout()`：

- 检查 `package/kernel/mac80211/Makefile`
- 如果已有 `-DNSS_FIRMWARE_VERSION_12_5` 则跳过
- 否则在 `C_DEFINES=` 后插入：

```make
ifeq ($(CONFIG_NSS_FIRMWARE_VERSION_12_5),y)
    C_DEFINES+=-DNSS_FIRMWARE_VERSION_12_5
endif
```

- 写入后再次检查，失败则终止构建，避免产出统计损坏的固件

`wrt_core/update.sh` 在 `update_ath11k_fw` 之后调用该函数。

### 2. 默认保持 ath11k 统计开启

`update_nss_pbuf_performance()` 在 `pbuf.uci` 的 `config general` 下增加：

```sh
option stats_disable '0'
```

同时把 `qca-nss-pbuf.init` 中的默认值从：

```sh
config_get stats_disable opt stats_disable 1
```

改为：

```sh
config_get stats_disable opt stats_disable 0
```

这样新安装和保留旧 `/etc/config/pbuf` 的升级设备都会默认启用 ath11k 统计。默认过滤/转发行为不变，只影响统计。

## 影响

- 新构建的 jdcloud / AP8220 / AX3600 会使用与 qca-nss-drv、ECM 一致的 12.5 peer stats 布局
- `iw station dump`、LuCI 关联客户端页面能持续显示速率、信号、RX/TX 计数
- `stats_disable=0` 会增加少量统计开销；如果更看重极限 Wi-Fi 吞吐，可手动改回：

```sh
uci set pbuf.opt.stats_disable='1'
uci commit pbuf
/etc/init.d/qca-nss-pbuf restart
```

- 已有固件需要重新构建才能生效；无法只靠 UCI 修复 ath11k 的结构体偏移

## 验证

- `bash -n wrt_core/modules/target_fixes.sh`
- `bash -n wrt_core/update.sh`
- 用 LibWrt 的 `mac80211/Makefile` 和 `pbuf.uci` 做本地模拟：
  - 确认插入 `-DNSS_FIRMWARE_VERSION_12_5`
  - 确认 `stats_disable '0'`
  - 重复执行保持幂等，不重复插入
