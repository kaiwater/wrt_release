# 2026-11-03 22:14 — CI: 给 OpenWrt 构建单独加 dl 缓存

## 背景

`build_wrt.yml` / `release_wrt.yml` 之前只缓存两样东西：

```yaml
path: |
  ./action_build/.ccache
  ./action_build/staging_dir
```

缓存 key 里带 `BUILD_DATE`，所以每次运行都是新 key，只能靠 `restore-keys`
前缀命中。这个策略对 `staging_dir`/`.ccache` 是合理的：构建产物需要按源码
revision 区分，旧缓存只作为"可用的近似起点"。

但 `make download` 没有被缓存。`dl/` 里的文件按"包名 + hash"命名，跨设备、
跨分支、跨多次构建的复用率很高；在 `staging_dir` 已经命中的情况下，
重新下载全部源码包反而成了主要耗时之一。

## 变更

新增一个独立的 `dl` 缓存，放在 `Compute Cache Key` 之后、
`Cache Dependencies` 之前（此时 `action_build/dl` 已由 `Pre Clone` 创建）：

```yaml
- name: Cache Downloads
  uses: actions/cache@v6.1.0
  with:
    path: ./action_build/dl
    key: ${{ matrix.os }}-${{ matrix.model }}-dl-${{ env.REPO_FLAG_HASH }}
    restore-keys: |
      ${{ matrix.os }}-${{ matrix.model }}-dl-
```

涉及：

- `.github/workflows/build_wrt.yml`
- `.github/workflows/release_wrt.yml`

### 为什么单独一把 key

- 原 key 含 `BUILD_DATE`，每次都是新 key；`dl` 需要稳定 key 才能跨次命中。
- 把 `dl` 塞进原缓存会让它跟着 `BUILD_DATE` 一起反复保存，浪费缓存配额。

### 为什么不会被“Delete Old Cache”误删

删除步骤只匹配：

```text
${os}-${model}-${REPO_FLAG_HASH}-
```

`dl` 的 key 是 `${os}-${model}-dl-...`，前缀不匹配，所以会保留。

## 影响范围

- 纯 CI 缓存，不改变固件内容、配置、默认值或构建产物。
- 第一次冷启动仍然要下载全部包；后续命中时 `make download` 基本直接跳过。
- `dl` 通常 1–2GB，会增加仓库缓存占用；GitHub 单仓库 10GB 上限，旧缓存有
  LRU 淘汰。如果确实过大，优先保留 `dl` + `.ccache`，再考虑缩小 `staging_dir`。
- 如果缓存里的包被上游删除/改名，`make download` 会按 hash 校验并重新下载，
  不会把坏文件带进构建。

## 验证

- 用 PyYAML 解析两个 workflow，语法通过。
- 未触发 GitHub Actions（本地没有 runner），实际命中率需要下次 CI 观察
  `Cache Downloads` 的 `Cache restored` 日志。

## 相关背景（本次未改动）

这次同时把 Time Advertisement 的调查结论记下来，避免下次重新踩：

- 抓包：元素 69 的 TimeValue = `2026-11-02 02:39:54 UTC`，beacon TSF =
  513755s；`TimeValue + TSF` 比真实时间超前 115.3 小时。
- 根因在 hostapd 用户态：它把“生成时的当前 UTC”填进了本应表示
  “TSF=0 时的 UTC”的字段，且元素只在 hostapd 启动 / wifi reload 时生成一次。
  上游 2019 年讨论已指出，2.12 仍未修。
- mtwifi（RAX3000M/WR30U/BE12）内部有 `AsicGetTsfTime`（64 位）和
  `HW_GET_TSF`（32 位），但没有 proc / ioctl / UCI 出口；要授时必须新增
  内核接口，风险较高，本次不实施。
- 结论：mt798x/mtwifi 目标暂不启用 `time_advertisement=2` 的正确授时；
  Gemtek BrightSpeed（mt76）可另测；ipq60xx/ipq807x（ath11k + NSS）没有 TSF。
