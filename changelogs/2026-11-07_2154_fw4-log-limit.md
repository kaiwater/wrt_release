# 2026-11-07 21:54 — fw4 日志限速（全机型默认）

## 背景

某台设备的 `dmesg` 被防火墙 DROP 日志刷满，585 行 ring buffer 里几乎全是：

```text
DROP-IOT-to-UPLAN: IN=br-iotlan OUT=br-wan-bypass ...
```

后果：

- 启动阶段的驱动日志（ath11k 等）被挤出 ring buffer，事后无法排查
- 单条规则在几秒内可以打出几十条日志，属于无意义重复

这条规则来自 `/etc/config/firewall` 里的普通 UCI rule：

```text
config rule
	option name 'DROP-IOT-to-UPLAN'
	option target 'DROP'
	option log '1'
```

fw4 支持 `log_limit`，但默认没有值，所以生成的是无限速的 `log prefix ...`。

## 变更

新增 `wrt_core/patches/993_firewall_log_limit`，由 `target_fixes.sh` 安装到：

```text
/etc/uci-defaults/993_firewall_log_limit
```

逻辑：

1. 仅在存在 `/sbin/fw4` 时执行（fw3/iptables 设备直接退出）
2. 遍历所有 firewall zone
3. 没有 `log_limit` 的 zone 补上 `10/minute`
4. 已有 `log_limit` 的 zone 保持不变
5. 有改动时 `uci commit firewall`

选择 zone 级而不是逐条 rule 的原因：

- fw4 的 `rule.uc` 在规则没有自己的 `log_limit` 时，会回退到所属 zone 的 `log_limit`（`limit name "<zone>.log_limit"`）
- 一个 zone 一条设置，覆盖该 zone 下现有和以后新增的日志规则
- 不需要逐条改 `/etc/config/firewall`

## 生效范围

| 场景 | 行为 |
|---|---|
| 使用 fw4 的机型 | 首次启动/升级后自动补齐 zone `log_limit` |
| 已有显式 `log_limit` | 保留原值 |
| fw3/iptables 机型 | 脚本直接跳过 |
| 已刷机、未升级的设备 | 需要手动执行或等下次刷机 |
| 运行中新建 zone | 不在脚本覆盖范围内（极少见） |

## 验证

- `sh -n` 语法检查通过
- 用模拟的 `uci` 环境测试：
  - 无 `log_limit` 的 zone 被补成 `10/minute`
  - 已有 `log_limit` 的 zone 保持不变
  - 第二次执行不重复提交（幂等）
- 未在真实设备上执行 `uci commit` / `fw4 reload`

## 手动应用（已刷机设备）

```sh
for z in $(uci show firewall | sed -n 's/^firewall\.\([^.=]*\)=zone$/\1/p'); do
    [ -n "$(uci get firewall.$z.log_limit 2>/dev/null)" ] || \
        uci set firewall.$z.log_limit='10/minute'
done
uci commit firewall
fw4 reload
```

注意 `fw4 reload` 会短暂重建防火墙规则，属于运行期操作，需要在维护窗口执行。
