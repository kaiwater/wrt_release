# 2026-10-27 02:58 — ath11k ddwrt 包名加固

## 变更

`wrt_core/modules/target_fixes.sh` 的 `update_ath11k_fw()`：

- 统一处理 `ipq50xx` / `ipq60xx` / `ipq807x` 的 `target.mk`。
- 新增处理 `target/linux/qualcommax/image/*.mk` 的设备 `DEVICE_PACKAGES`。
- 将以下旧包名统一改成 `-ddwrt`：
  - `ath11k-firmware-ipq5018`
  - `ath11k-firmware-ipq6018`
  - `ath11k-firmware-ipq8074`
  - `ath11k-firmware-qcn9074`
- 增加 grep 校验：如果还有未转换的旧包名，直接报错退出。
- 保留 `ath11k-firmware-ipq5018-qcn6122` 不变（该包在 ddwrt Makefile 中仍使用原名称）。

## 原因

jdcloud CS-02 构建在 target install 阶段失败：

```text
ERROR: unable to select packages:
  ath11k-firmware-qcn9074 (no such package):
    required by: world[ath11k-firmware-qcn9074]
```

`ath11k_fw.mk` 只定义了 `-ddwrt` 包名，但 `image/ipq60xx.mk` 里 CS-02 的默认 `DEVICE_PACKAGES` 仍写死 `ath11k-firmware-qcn9074`。重写 image mk 后，设备包列表与 Makefile 一致。

参考了 LibWrt 衍生仓库（如 `Nan7Li/jdcloud-re-cs-02-libwrt-eg25g-unofficial`）的 build.config：其中同时存在 `ath11k-firmware-qcn9074-ddwrt` 和默认 `ath11k-firmware-qcn9074` 的痕迹，但本仓库使用 apk，且 Makefile 已被替换为 ddwrt-only，因此在自己的构建链里必须让所有引用统一到 `-ddwrt`。

## 影响范围

- 所有使用 `update_ath11k_fw()` 的 qualcommax 构建。
- 不改变非 qualcommax 目标。
- 不会重复添加 `-ddwrt` 后缀（sed 使用 `[^-[:alnum:]_]` 边界）。

## 验证

- `bash -n wrt_core/modules/target_fixes.sh` 通过。
- `config_preview` 通过（CS-02 / AP8220 / AX3600）。
- 未执行完整编译；下一次构建验证 target install 阶段。

## 风险与回滚

- 风险：未来 image mk 新增其他 ath11k 包名时，校验会报错。此时按实际包名补充转换规则。
- 回滚：恢复 `update_ath11k_fw()` 只处理 target.mk 的旧版本，但 apk 构建会重新出现缺包问题。
